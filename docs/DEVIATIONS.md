Each entry says what the spec or build prompt expects, what we do instead, the evidence, and when to revisit it. Newest last.

| D-03 | kind | — | `KubeletConfiguration.failCgroupV1: false` in `deploy/kind/cluster.yaml` | Docker 29.3.1 on this VM runs **cgroup v1** (`docker info`: `CgroupVersion 1`, cgroupfs); the 1.35+ kubelet refuses cgroup v1 by default. | D-04 | kind | — | containerd CRI `restrict_oom_score_adj = true` (`containerdConfigPatches`) | First two `kind create` attempts failed: every pod sandbox died with `runc create failed ... nsexec: failed to update /proc/self/oom_score_adj: Permission denied`. Root cause: the VM drops **CAP_SYS_RESOURCE** from every bounding set (`CapBnd: 000001fffeffffff`, bit 24 cleared), so even host root cannot lower `oom_score_adj` (`echo -500 > /proc/self/oom_score_adj` → Permission denied). The setting clamps requested scores instead of failing. Cluster then came up in 12 s. Side effect: kubelet's OOM-score protection of system pods is a no-op here, so under memory pressure the kernel may kill a control-plane container as readily as an app | Laptops and real clusters don't need it |
| D-05 | Images | `golang`, `python`, `postgres:18.6`, distroless, pulled by the cluster | **Pull on the host, side-load into kind** (`scripts/kind-load-images.sh`, `app/build-images.sh`). (2) `gcr.io` (distroless) is not allowlisted (`Forbidden`). (3) kind copies the host's `HTTPS_PROXY=http://127.0.0.1:<port>` into the node, where 127.0.0.1 is the node itself: `crictl pull` → `proxyconnect tcp: dial tcp 127.0.0.1:...: connection refused`. (4) Docker 29's containerd image store saves multi-platform indexes whose other-arch blobs were never pulled; `kind load docker-image` then fails with `ctr: content digest ... not found`. Fixed by `docker save --platform linux/amd64` + `kind load image-archive` | M2: every chart image must be added to the side-load list. Consider a Docker Hub token as an environment secret if 429s recur |
| D-06 | Toolchain | Go 1.27, Node 24 | Go **1.24.7** (preinstalled) with modules pinned to the last releases that support it: `go.opentelemetry.io/otel` **v1.41.0**, `otelhttp` **v0.66.0**, `pgx/v5` **v5.8.0**, `otelpgx` **v0.10.0**.
